После переезда в `FamilyCore` эти номера остаются без хозяина — как ядро нумерует своё, решается при его заведении (План, Этап 8).

### Подмодуль ядра

Действует с перевода «Трапезы» на `FamilyCore` (Р-46).

- Клон репозитория — только `git clone --recurse-submodules`; иначе `src/shared` пустая и сборка падает непонятной ошибкой
- Правка ядра — **два коммита в двух репозиториях**: сначала в `src/shared` с его тестами, потом указатель в приложении. Забытый указатель означает, что правки нет ни у второго устройства, ни в CI
- Перед пушем — `git status` обязан быть чистым **и в подмодуле тоже**
- Правка ядра ради одного приложения — повод остановиться: либо параметр в `AppConfig`, либо это не ядро
- Поломка в ядре чинится один раз, в `FamilyCore`; непереведённые приложения получают её отдельными сессиями из их корней

## Разделение работы

**Claude Code — и «что строить», и «как».** Продуктовые развилки и пересмотры архитектуры — тоже здесь: он видит настоящие файлы и проверяет факты. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой**, для свободного разговора без кода и для картинок. Его итог приходит в репозиторий потоком ниже.

### Планирование в Claude Code

1. Сессия планирования из корня репозитория — заготовка в «Шаблонах»
2. Решения — в `05-Решения` в момент выбора; правки `01`, `02`, `03` — по ходу. В режиме планирования, когда писать можно только файл плана, решение пишется туда готовой записью в момент выбора и переносится в `05` дословно
3. Конец: Журнал, передача, коммит документов, дерево чистое
4. `/clear` — и код новой сессией по плану. Контекст планирования в неё не переезжает: память — документы

## Поток изменений из чата: чат → документы → код

1. Обсуждаем крупное изменение в чате
2. На выходе — готовые куски markdown для вставки: запись в `05-Решения`, правки `01-Проект` и `02-Архитектура`
3. Отдельным пунктом — что придётся переделать в уже написанном коде
4. Вставляем, коммитим
5. Следующая сессия Claude Code начинается со сверки

## Обратный поток: код → чат

То, что Claude Code в конце сессии называет «не описано в документах», возвращается в обсуждение, а не решается на месте.

## Правила ведения документов

- **Не менять задним числом.** Отмена решения — новая запись со ссылкой
- **Решения записываются в момент выбора**
- **Журнал обновляется в конце каждой сессии**
- **Перед пушем — `npm test`, `npm run build`, `npm run smoke`**, итог по коду выхода, а не по выводу
- **Прогон проверяется порчей кода**, когда меняется его сценарий: сломанная строка экрана обязана дать код 1
- **Прогон ходит в IndexedDB сам.** `scripts/smoke.mjs` открывает базу `trapeza` напрямую — снимает `seenChanges`, читает `folds`. Правило «к хранилищу только через `core/db.ts`» — про код приложения; прогон смотрит на собранный `dist` снаружи, из браузера (Р-43)
- **Порча — в отдельной рабочей копии, а не в основной папке:** `git worktree add ../Trapeza-spoil HEAD`, `node_modules` — переходом на основные (`mklink /J`), после — `git worktree remove --force ../Trapeza-spoil`. Так же, как в «Делу Время»
- **Видимое изменение — строка в `src/changes.ts`** в том же коммите
- **План содержит только предстоящее**
- **Цифра со сводного листа или экрана — вместе с формулой**, из которой она посчитана (Журнал, 15.09.2026, ошибка с «домашней едой»)
